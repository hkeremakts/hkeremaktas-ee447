W6·02

The masked GPIODATA address

Trace

Bits 9:2 of the address used to access GPIODATA select which pins the access affects (slide 15).

  1. Which address reads or writes only PF4 and PF0?
  2. Which address covers PB3–PB0 only?
  3. Which address reads all 8 pins of Port A?
  4. PF3–PF0 are outputs and GPIODATA's pins currently read 0x06. This runs:
	LDR	R1, =0x40025030	MOV	R0, #0xFF	STR	R0, [R1]

Which pins change, and what do PF3–PF0 read afterwards?

  1. Next, LDR R0, [R2] runs with R2 = 0x40025018. What is R0: 0x03, 0x06, or something else?
Hint Mask = the pins you want as an 8-bit value. Address = base + (mask << 2). The data bits themselves stay in their normal positions.

a) Mask 0001 0001 = 0x11, shifted left by 2 = 0x44, so 0x40025044.

b) Mask 0x0F → 0x3C, so 0x4000503C (the slides' polling example uses this one).

c) Mask 0xFF → 0x3FC, so 0x400043FC.

d) 0x030 >> 2 = 0x0C = 0000 1100, so only PF3 and PF2 are written; both become 1. PF1 and PF0 keep their values. 0x06 becomes 0x0E.

e) 0x018 >> 2 = 0x06: PF2 and PF1 are read, everything else reads 0. The bits are not shifted, so R0 = 0x06, not 0x03.

See also: Valvano, Embedded Systems: Introduction to Arm Cortex-M, section 4 ("bit-specific addressing", Program 4.11 and exercises 4.8–4.9).

W6·03

Change two LEDs with one store

Code

The LaunchPad's RGB LED is on PF1 (red), PF2 (blue) and PF3 (green); Port F is already set up with PF3–PF1 as outputs. Turn red off and green on, and leave blue exactly as it is. Use one STR and don't read GPIODATA.

Hint Pick the GPIODATA address whose mask contains only PF3 and PF1. Then the value you store only needs the right bits for those two pins.

Code

Hint Every step is LDR, ORR or BIC, STR. PCTL has 4 bits per pin: PF4–PF1 are bits 19–4, mask 0x000FFFF0. That mask doesn't fit an immediate, so load it with LDR =.

The two NOPs after the clock write match slide 43: the port needs a few cycles before its registers respond. See also: Valvano, Program 4.1 (both LaunchPad switches and the LED).

Bug hunt

This code is meant to set up both LaunchPad switches, SW1 on PF4 and SW2 on PF0, as inputs with pull-ups. SW1 works, but PF0 always reads 0, and its PUR and DEN bits stay 0 even though the code sets them. Find the cause and fix the code (it's the starter code in the simulator).

	; clock on, then:	LDR	R1, =GPIO_PORTF_DIR	LDR	R0, [R1]	BIC	R0, R0, #0x11	STR	R0, [R1]	LDR	R1, =GPIO_PORTF_PUR	LDR	R0, [R1]	ORR	R0, R0, #0x11	STR	R0, [R1]	LDR	R1, =GPIO_PORTF_DEN	LDR	R0, [R1]	ORR	R0, R0, #0x11	STR	R0, [R1]
  1. Why are the writes to PF0's bits ignored?
  2. Add the missing steps.
  3. Why would MOV R0, #0x01 / STR R0, [CR] break SW1?
Hint Slides 34–35: GPIOLOCK and GPIOCR. Which pins does TI protect, and what does a 0 bit in GPIOCR do to writes to AFSEL, PUR, PDR and DEN?

a) PF0 is one of the protected pins (it can be the NMI input). After reset GPIOCR bit 0 is 0, and GPIOCR decides which bits of AFSEL, PUR, PDR and DEN a write may change. So the PUR and DEN writes keep bit 0's old value.

b) Before setting PUR and DEN: write 0x4C4F434B to GPIOLOCK (0x40025520), then set bit 0 of GPIOCR (0x40025524). Only after the unlock does GPIOCR accept writes.

c) GPIOCR = 0x01 would let only PF0's bits change. The later ORR into PUR and DEN would then lose bit 4, so SW1 would stop working. Use ORR (or write 0x1F) so the other pins stay committed. The simulator models this, so you can try it.

W6·07

Pull resistors, LEDs and pin types

Concept
  1. A push button connects PB2 to ground when pressed. Which internal resistor do you enable, and what does PB2 read when the button is pressed and when it's released?
  2. The same button, but it connects PB2 to 3.3 V.
  3. An LED's anode goes to 3.3 V through a resistor and its cathode to PF2. Is the pin sourcing or sinking current, and what do you write to turn the LED on?
  4. What happens to an input pin with no pull resistor when the button is open?
  5. Several devices share one line (as in I²C). Why must their pins be open-drain, and what makes the line 1?
  6. What does the Schmitt trigger on an input do for a slow or noisy signal?
Hint With the button open, only the resistor decides the level. Think about which way current flows through the LED.
PartResistorReads
aPull-up (GPIOPUR)Pressed: 0, released: 1 ("negative logic")
bPull-down (GPIOPDR)Pressed: 1, released: 0

c) Current flows from 3.3 V through the LED into the pin, so the pin sinks current (common-anode style). Write 0 to turn it on, 1 to turn it off.

d) It floats: nothing sets its level, so it can read 0 or 1 at random and pick up noise.

e) An open-drain pin can only pull the line to 0 or let go (high impedance). If two push-pull pins drove 1 and 0 at once, they would short. With open-drain any device can pull the line low safely, and a pull-up resistor makes it 1 when nobody pulls.

f) It uses two thresholds (VT+ to switch to 1, VT− to switch back to 0), so a signal wobbling around one level doesn't toggle the input many times.

W6·08

Which switch is pressed? (polling)

Code

Four switches are on PB3–PB0 with pull-downs (pressed = 1); PB7–PB4 are outputs used by other code. Write READSW: return in R0 the number of the lowest pressed switch, 1 for PB0 up to 4 for PB3, or 0 if none is pressed. Read only PB3–PB0, through their masked address.

In the simulator, click the input pins under Port B to press switches, then Run.

Hint Load from the address with mask 0x0F, so PB7–PB4 always read 0. Then shift right with LSRS until a 1 falls into the carry, counting the shifts.

The masked address 0x4000503C returns only bits 3–0, so the outputs on PB7–PB4 can't confuse the test (one of the checks has them at 1). If nothing is pressed, CBZ skips the loop. Otherwise each LSRS moves the lowest bit into C, and the loop stops at the first 1. This is the slides' polling example (slide 70) turned into a subroutine; a main loop would call it until R0 ≠ 0.

W6·10

Scan a keypad

Code

A 4×3 keypad (slides 52–61) has its rows on PD3–PD0 (outputs) and its columns on PD6–PD4 (inputs with pull-ups). Pressing a key connects its row to its column. Keys are numbered row by row: 1 2 3 / 4 5 6 / 7 8 9 / * 0 #, so row r (0–3) and column c (0–2) give the code 3r + c.

Write KEYSCAN: drive one row low at a time (the others high), read the columns, and return R0 = 3r + c for the pressed key, or 0xFF if none. Before returning, drive all rows low again, so a key press can be detected (slide 60). Assume at most one key is pressed.

In the simulator, click a key on the keypad, then Run.

Hint The row pattern is 1 << r, inverted in its low 4 bits (EOR #0x0F). The columns read 1 unless pressed; shift them down by 4 and invert them with EOR #0x07, so the pressed column becomes a 1 bit.

For each row r: write ~(1 << r) to the rows through 0x4000703C (mask 0x0F), then read the columns through 0x400071C0 (mask 0x70). Only the column of a key in the low row reads 0. After LSR #4 and EOR #0x07, a non-zero value means "found", and the position of its 1 bit is the column. ADD R0, R0, R3, LSL #1 plus ADD R0, R0, R3 adds 3r without a multiply.

Pressing two keys in different rows of the same column would connect a high row to a low row through the keys (slide 61's short circuit); real designs add diodes or use open-drain rows. See also: Zhu, Embedded Systems with ARM Cortex-M Microcontrollers, section 14.9 (keypad scan).

W6·11

Pick the interrupt settings

Concept

For each case give the bit values for the pin in GPIOIS, GPIOIBE and GPIOIEV (write x if the bit doesn't matter).

  1. SW1 on PF4 (pull-up, pressed = 0): interrupt on each press.
  2. PB2: interrupt on every change, press and release.
  3. PD1: interrupt as long as the pin is high.
  4. PB4 with a pull-down (pressed = 1): interrupt on each press.
  5. For case (a), list everything else that must be set before the CPU actually runs GPIOF_Handler.
Hint IS: 0 = edge, 1 = level. IBE = 1 means both edges and makes IEV irrelevant. IEV: 1 = rising edge or high level, 0 = falling edge or low level.
PartISIBEIEVMeaning
a000falling edge

e) The full chain from Week 5's slide 45:

  1. GPIOICR bit 4 = 1, to clear an old flag.
  2. GPIOIM bit 4 = 1, so PF4's flag reaches the NVIC.
  3. NVIC: Port F is IRQ 30, so ISER0 bit 30 (and its priority in IPR7, byte 2).
  4. PRIMASK = 0 (CPSIE I).

Port B is IRQ 1. The whole port shares one IRQ, so the handler must check which pin caused it.

W6·12

Interrupt on SW1

Code

Port F is already set up with PF4 as an input with pull-up. Configure a falling-edge interrupt on PF4, clear any old flag, unmask it, enable IRQ 30 in the NVIC with priority 2, and finally switch interrupts on globally. Don't change other pins' bits in GPIOIS, IBE, IEV or IM.

Hint Clear the flag before unmasking, otherwise an old flag interrupts at once. For the NVIC part, reuse Week 5: ISER0 bit 30, and IPR7 byte 2 with priority 2 << 5.

IS, IBE and IEV: BIC bit 4 (edge, one edge, falling). ICR: a plain store of 0x10 is enough, because writing 0 to ICR has no effect. IM: ORR 0x10. IPR7 byte 2 = 0x40, so 0x11223344 becomes 0x11403344. ISER0 = 0x40000000. Then CPSIE I.

One handler for two switches

Code

SW1 (PF4) and SW2 (PF0) both have falling-edge interrupts, so both use GPIOF_Handler. Write the handler: SW1 toggles the red LED (PF1), SW2 toggles the green LED (PF3), and both can be pending at once. Blue (PF2) must not change.

  • Find the source with GPIOMIS, so masked pins are ignored.
  • Clear only the flags you handled.
  • R0–R3 and R12 are free (the hardware saves them on entry); keep R4–R11.
Hint Read MIS into a register and keep it: TST each bit, EOR the LED bits, write the LEDs through the PF3/PF1 masked address, and finally store the MIS value into ICR.

Reading MIS gives exactly the unmasked pins that interrupted. Writing that same value to ICR clears those flags and nothing else, so a flag of a masked pin (PF2 in the last check) stays set. Without clearing, the handler would run again right after returning, forever (slide 72).

Toggling through 0x40025028 (PF3 and PF1 only) means blue can't change, even though R2 also holds other bits. This is a polled interrupt inside a vectored system: the port has one vector, and the handler polls which pin it was.

W6·14

Interrupt pitfalls

Concept
  1. An edge-triggered GPIO handler forgets to write GPIOICR. What happens after it returns?
  2. A button is set up as a level interrupt (low level) and held down for one second. What happens, and why is edge-triggering better for a button?
  3. A press counter counts 3 for a single press. What is the cause, and give two ways to fix it.
  4. Two switches: on PF4 and PF0, or on PF4 and PB0. How does finding the source differ?
  5. Slide 74's main loop is WFI / B Loop. What does WFI do, and why is it better than an empty loop?
Hint Think about RIS: when does it go back to 0 for edge interrupts, and for level interrupts?

a) RIS stays 1, so the interrupt is still requested. As soon as the handler returns it is entered again, forever, and main never runs again.

b) A level interrupt stays requested as long as the pin is low, so the handler runs again and again for the whole second. An edge interrupt fires once per press.

c) Bouncing: the contacts make and break several times in the first few milliseconds, so one press gives several edges. Fixes: a hardware RC filter (with the Schmitt trigger), or software: after the first edge, ignore the pin for about 10–20 ms (for example clear its IM bit and set it again later from a timer), or check that the level is still the same after a short delay.

d) PF4 and PF0 share Port F's single vector, so one handler must read MIS to see which pin it was (polled, inside the handler). PF4 and PB0 are on different ports with different vectors (IRQ 30 and IRQ 1), so each switch gets its own handler (vectored). See also: Valvano, Example 9.1, which solves the same task both ways.

e) WFI (wait for interrupt) puts the core to sleep until an interrupt arrives, which saves power. An empty loop keeps the CPU busy doing nothing.
