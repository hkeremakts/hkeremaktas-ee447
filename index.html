PUSH and POP order

Trace

R1 = 1, R2 = 2, R3 = 3, R7 = 7 and SP = 0x20000400. These instructions run in order:

PUSH	{R3,	R1, R7, R2}POP	{R4,	R5}POP	{R0}
  1. After the PUSH: what is SP, and what is stored at 0x200003F0, 0x200003F4, 0x200003F8 and 0x200003FC?
  2. After both POPs: what are R0, R4, R5 and SP?
Hint The order you write the registers in doesn't matter. The lowest-numbered register always goes to the lowest address.

a) Four words, so SP = 0x20000400 − 16 = 0x200003F0.

AddressContents

W5·02

Reverse an array with the stack

Code

Six words are stored in memory: 1, 2, 3, 4, 5, 6. Reverse them in place, so the memory holds 6, 5, 4, 3, 2, 1, using the stack. SP must be back at its starting value at the end.

Hint Push the elements one by one while walking forward through the array. The last one pushed is the first one popped.

The push loop leaves 6 on top of the stack, so the pop loop writes 6 first. Both loops walk forward with post-indexing ([r0], #4), which is why R0 is reset to the start in between. Six pushes and six pops leave SP where it began.

A version without a loop also works for a fixed size: load six registers, PUSH {R1-R6}, then pop them one at a time in reverse (POP {R6}, POP {R5} …), and store them back.

Solution
	AREA	mydata, DATA, READWRITE	; the array, at 0x20000040ARR	DCD	1, 2, 3, 4, 5, 6N	EQU	6 	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	LDR	R0, =ARR		; r0 = read pointer	MOV	R1, #N			; r1 = counterpush_loop	LDR	R2, [R0], #4		; next element	PUSH	{R2}			; last element ends up on top	SUBS	R1, R1, #1	BNE	push_loop 	LDR	R0, =ARR		; write pointer back at the start	MOV	R1, #Npop_loop	POP	{R2}			; comes out in reverse order: 6, 5, 4 ...	STR	R2, [R0], #4	SUBS	R1, R1, #1	BNE	pop_loopstop	B	stop			; ARR = 6 5 4 3 2 1, SP back at 0x20000400 	ALIGN	END
W5·03

PUSH without PUSH

Code

Write code that does exactly what PUSH {R2, R5} does, then exactly what POP {R2, R5} does, without using PUSH, POP, STM or LDM. Use STR and LDR with SP (ADD/SUB on SP are allowed too). The memory layout must be identical to the real PUSH. The starter puts 0x22 in R2 and 0x55 in R5.

Hint Full descending means "decrement first, then store". That's pre-indexing with !. Which register has to be stored first so that R2 ends up at the lower address?

PUSH puts R2, the lower-numbered register, at the lower address, so R5 must be stored first: STR R5, [SP, #-4]!, then STR R2, [SP, #-4]!. POP is the mirror image, with post-indexing: load R2 first from the lowest address, LDR R2, [SP], #4, then R5. This is exactly what STMDB SP! (decrement before) and LDMIA SP! (increment after) do.

Solution
	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	MOV	R2, #0x22	MOV	R5, #0x55	; same as PUSH {r2, r5}: higher register first, so r2 ends at the lower address	STR	R5, [SP, #-4]!		; SP = SP - 4, then store r5	STR	R2, [SP, #-4]!		; SP = SP - 4, then store r2   (SP now points at r2)	MOV	R2, #0			; destroy both registers	MOV	R5, #0	; same as POP {r2, r5}: lower register first, from the lower address	LDR	R2, [SP], #4		; load r2, then SP = SP + 4	LDR	R5, [SP], #4		; load r5, then SP = SP + 4stop	B	stop 	ALIGN	END

W5·06

Count the 1 bits

Code

Write COUNT1S: return in R0 the number of 1 bits in R0. For example 0xF00F0001 gives 9. All other registers unchanged. Try to use the carry flag.

Hint LSRS shifts the lowest bit out into the carry flag. ADC R0, R0, #0 adds that carry. Stop when the shifted value becomes 0.

LSRS does two jobs: C = the bit shifted out, and Z = 1 once nothing is left. ADC without the S suffix adds the carry but leaves the flags alone, so BNE still tests the LSRS result. The loop runs only as many times as the position of the highest 1 bit.

Why doesn't it return?

Bug hunt

This program should end with R0 = 27:

__main	MOV	R0, #3	BL	CUBEstop	B	stop CUBE	MOV	R1, R0	BL	SQ	MUL	R0, R0, R1	BX	LR SQ	MUL	R0, R0, R0	BX	LR

  2. Fix it, and also make CUBE leave R1 unchanged.
Hint What does BL SQ do to LR? What address is in LR when CUBE reaches its own BX LR?

a) BL CUBE puts the return address (the stop line) in LR. Inside CUBE, BL SQ overwrites LR with the address of the MUL in CUBE. SQ returns there and R0 = 9 × 3 = 27. Then CUBE's BX LR jumps to that same MUL again: R0 = 81, then 243 … The program loops forever and never returns to main.

b) PUSH {R1, LR} at the start of CUBE and POP {R1, LR} before its BX LR. Any subroutine that calls another one with BL must save LR. This is the QUAD/SQ example from the slides.

Code

The main program passes two arguments on the stack:

MOV	R4,	#0x44			; test: DIFF must give R4, R5 backMOV	R5,	#0x55MOV	R1,	#50			; aMOV	R2,	#8			; bPUSH	{R1,	R2}MOV	R1,	#0			; the arguments now exist only on the stackMOV	R2,	#0BL	DIFFADD	SP,	SP, #8

  1. Once DIFF has saved what it needs on the stack, at which SP offsets are a and b?
  2. Why does main need ADD SP, SP, #8?
Hint Draw the stack. After main's push, a is at [SP] (R1 is the lower register). Anything DIFF pushes itself moves SP further down.

DIFF uses R4 and R5, so it must save them: PUSH {R4, R5} at the start, POP {R4, R5} before returning.

Recursive factorial

Code

Write a recursive FACT: R0 = n, returns R0 = n!, with 0! = 1! = 1 (n ≤ 12 so it fits in 32 bits). When it returns, every register except R0 must have its original value (Check tests this).

Extra question: for n = 5, what is the lowest value SP reaches with your code?

Hint End condition first: n ≤ 1 returns 1. Otherwise keep n somewhere that survives the call (a pushed register), call FACT(n − 1), then multiply.

Each level saves its own n and its return address with PUSH {R1, LR}. Because the end-condition test comes before the PUSH, the calls for 5, 4, 3 and 2 each push 8 bytes, and the call for 1 returns at once. That's 4 × 8 = 32 bytes, so the lowest SP is 0x200003E0. If your code pushes before testing, the call for 1 pushes too, and the answer is 0x200003D8. Both are correct for their code.

Solution
	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	MOV	R0, #5	BL	FACT			; r0 = 120stop	B	stop ; FACT: r0 = n -> r0 = n!   (n <= 12 so the result fits in 32 bits)FACT	CMP	R0, #1	BHI	f_rec			; n > 1: recursive case	MOV	R0, #1			; end condition: 0! = 1! = 1	BX	LRf_rec	PUSH	{R1, LR}		; this call's n and return address	MOV	R1, R0			; r1 = n	SUB	R0, R0, #1	BL	FACT			; r0 = (n-1)!	MUL	R0, R0, R1		; r0 = n * (n-1)!	POP	{R1, LR}	BX	LR 	ALIGN	END

DELAY_MS

Code

Assume a 16 MHz clock, SUBS = 1 cycle, and BNE = 2 cycles when it jumps back (taken) or 1 cycle when it falls through on the last pass (not taken).

  1. How many cycles does one pass of a SUBS / BNE loop take, for a pass that jumps back, and for the last pass?
  2. How many passes make 1 ms?
  3. Write DELAY_MS: R0 = number of milliseconds, with nested loops. All registers unchanged.
  4. Why can't the count from (b) be loaded with MOV R1, #…?
Hint 1 ms at 16 MHz is 16 000 cycles. The inner loop delays 1 ms, and the outer loop repeats it R0 times.

a) A pass that jumps back: 1 + 2 = 3 cycles. The last pass: 1 + 1 = 2 cycles. Every pass except the last jumps back, so for long loops count 3 per pass.

b) 16 000 / 3 ≈ 5333 passes. The outer loop adds a few cycles per millisecond, which is negligible.

d) 5333 = 0x14D5 needs 13 bits. A Thumb-2 MOV immediate is an 8-bit pattern that can be shifted (or 0–255 directly), and 0x14D5's 1 bits are spread too far apart for that. Use LDR R1, =5333 or MOVW instead.

Solution
	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	MOV	R0, #2			; 2 ms	BL	DELAY_MSstop	B	stop ; DELAY_MS: waits about r0 milliseconds at 16 MHz. All registers unchanged.; Inner loop: SUBS (1) + BNE taken (2) = 3 cycles -> 16000 / 3 = 5333 passes per msONE_MS	EQU	5333DELAY_MS	PUSH	{R0, R1}	CMP	R0, #0	BEQ	d_doned_outer	LDR	R1, =ONE_MS		; 5333 does not fit a MOV immediate: use LDR =d_inner	SUBS	R1, R1, #1	BNE	d_inner	SUBS	R0, R0, #1		; one millisecond done	BNE	d_outerd_done	POP	{R0, R1}	BX	LR 	ALIGN	END

Enable interrupts in the NVIC

Code

Enable IRQ 1 (GPIO Port B), IRQ 30 (GPIO Port F) and IRQ 37. ISER0 is at 0xE000E100 and ISER1 at 0xE000E104.

  1. For each IRQ: which register, and which bit?
  2. Write the code.
  3. Why don't you need to read the register first and OR your bits in?
Hint Register number = IRQ DIV 32. Bit = IRQ MOD 32.

a)

IRQRegisterBit
1ISER0 (0xE000E100)1
30ISER0 (0xE000E100)30
37ISER1 (0xE000E104)5

c) In a set-enable register, writing a 0 bit has no effect, and only 1 bits enable. A plain STR can't switch anything off by accident. Turning interrupts off is done through a separate register, ICER.

W5·18

Set an interrupt priority

Code

Set the priority of IRQ 30 to 5. The IPR registers start at 0xE000E400, with 4 IRQs per register and 8 bits per IRQ. The TM4C uses only the top 3 bits of each byte.

  1. Which register address, and which bits?
  2. What byte value encodes priority 5?
  3. Write the code without changing the other three IRQs in that register. (In the simulator the register starts as 0x11223344.)
Hint Register = IRQ DIV 4, byte = IRQ MOD 4. "Top 3 bits" means the priority is shifted left by 5.

a) 30 DIV 4 = 7, so 0xE000E400 + 4 × 7 = 0xE000E41C. 30 MOD 4 = 2, so byte 2 = bits 23–16.

b) 5 = 0b101 in bits 7–5: 0b1010_0000 = 0xA0.

c) Read-modify-write: clear byte 2 with BIC, set it with ORR (0xA0 shifted left by 16), and store. The NVIC priority registers can also be written one byte at a time: STRB of 0xA0 to 0xE000E41E does the same in one store.

Solution
NVIC_PRI7	EQU	0xE000E41C	; 0xE000E400 + 4 * (30 DIV 4)	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	; IRQ 30: register 30 DIV 4 = 7, byte 30 MOD 4 = 2 -> bits 23:16	; TM4C uses the top 3 bits of each byte: priority 5 -> 5 << 5 = 0xA0	LDR	R1, =NVIC_PRI7	LDR	R0, [R1]	BIC	R0, R0, #0x00FF0000	; clear IRQ 30's byte, keep IRQ 28, 29, 31	ORR	R0, R0, #0x00A00000	; 0xA0 << 16	STR	R0, [R1]stop	B	stop 	ALIGN	END
W5·19

Stacking on interrupt entry

Trace

The processor is in thread mode, using MSP = 0x20000400. An interrupt arrives. At that moment R0 = 0x10, R1 = 0x11, R2 = 0x12, R3 = 0x13, R12 = 0x1C, LR = 0x08000321, the address of the next instruction is 0x08000100, and xPSR = 0x01000000.

  1. What is SP after stacking?
  2. What is at each address from the new SP up to 0x200003FC?
  3. What value does LR hold inside the ISR, and what does it mean?
  4. How does the ISR's BX LR know to unstack instead of jumping to a normal address?
Hint 8 registers are stacked automatically, with R0 at the lowest address and xPSR at the highest (the slides' stacking picture).

a) 8 words = 32 bytes, so SP = 0x200003E0.

AddressContents
0x200003E0R0 = 0x10
0x200003E4R1 = 0x11
0x200003E8R2 = 0x12
0x200003ECR3 = 0x13
0x200003F0R12 = 0x1C
0x200003F4LR = 0x08000321
0x200003F8PC = 0x08000100 (where to continue)
0x200003FCxPSR = 0x01000000

c) LR = 0xFFFFFFF9 (EXC_RETURN): return to thread mode and use the main stack.

d) 0xFFFFFFFx is not a valid code address. When it's loaded into PC, the processor recognises it as an exception return, pops the 8 registers and continues at the stacked PC (0x08000100).

An ISR that uses R4 and calls a subroutine

Code

Write SysTick_Handler, which adds 1 to a word in memory called TICKS. Inside, it must use R4 as the address register and call a subroutine INC_WORD that increments the word at [R4]. When either routine returns, every register must have its original value (Check tests this; the test main keeps 0x44 in R4).

  1. Which registers does the handler have to save itself, and why not R0–R3?
  2. Why must LR be saved here, even though it's an ISR?
Hint Which 8 registers does the hardware stack? Which value is in LR while an ISR runs?

a) R4 (and any of R4–R11 it uses). R0–R3, R12, LR, PC and xPSR are already stacked by the hardware on entry.

b) Inside the ISR, LR holds EXC_RETURN (0xFFFFFFF9). BL INC_WORD overwrites it. Without saving it, the final BX LR would jump back into the handler instead of returning from the interrupt.

Solution
	AREA	vars, DATA, READWRITETICKS	DCD	0	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	MOV	R4, #0x44		; main's own data in r4	BL	SysTick_Handler		; (here called by hand, to test it)	BL	SysTick_Handler		; TICKS = 2, r4 still 0x44stop	B	stop ; An ISR that uses r4 and calls a subroutine.; r0-r3, r12, LR, PC, xPSR are saved by the hardware; r4 and the; EXC_RETURN value in LR are the ISR's own job.SysTick_Handler	PUSH	{R4, LR}		; r4: not saved by hardware; LR: BL below overwrites it	LDR	R4, =TICKS	BL	INC_WORD		; add 1 to the word at r4	POP	{R4, LR}	BX	LR			; LR = 0xFFFFFFF9 again -> hardware unstacks INC_WORD	PUSH	{R0}	LDR	R0, [R4]	ADD	R0, R0, #1	STR	R0, [R4]	POP	{R0}	BX	LR 	ALIGN	END
W5·21

A 64-bit counter with interrupts off

Code

Write INC64: a 64-bit counter is stored as two words, low word first. Add 1 to it, with the carry going into the high word, so 0x1_FFFFFFFF becomes 0x2_00000000. Interrupts must be off during the update. When it returns, every register (and PRIMASK) must have its original value (Check tests this).

  1. Write it, using MRS / MSR PRIMASK and CPSID I.
  2. Why restore the old PRIMASK value at the end instead of just using CPSIE I?
Hint ADDS on the low word sets the carry. ADC on the high word adds it.

b) The caller may already have interrupts disabled for its own critical section. CPSIE I would switch them back on in the middle of the caller's work. Saving PRIMASK with MRS and restoring it with MSR leaves things exactly as they were.

Why disable at all: an interrupt that runs between the two stores could see a half-updated counter (new low word, old high word).

Solution
	AREA	vars, DATA, READWRITECOUNT64	DCD	0xFFFFFFFF, 0x00000001	; low word, high word = 0x1_FFFFFFFF	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	BL	INC64			; COUNT64 = 0x2_00000000stop	B	stop ; INC64: adds 1 to the 64-bit counter. No interrupt may run between the; read and the write, so interrupts are disabled - and afterwards PRIMASK; is put back as it was (the caller may already have them disabled).INC64	PUSH	{R0-R3}	MRS	R3, PRIMASK		; remember the old state	CPSID	I			; PRIMASK = 1: interrupts off	LDR	R2, =COUNT64	LDR	R0, [R2]		; low word	LDR	R1, [R2, #4]		; high word	ADDS	R0, R0, #1		; low + 1, carry out into C	ADC	R1, R1, #0		; high + carry	STR	R0, [R2]	STR	R1, [R2, #4]	MSR	PRIMASK, R3		; restore (not CPSIE I)	POP	{R0-R3}	BX	LR 	ALIGN	END
W5·22

BASEPRI

Concept

On the TM4C (3 priority bits), you want to block every interrupt with priority value 3 to 7, while still allowing priority values 0, 1 and 2.

  1. What value goes into BASEPRI, and with which instructions?
  2. How do you remove the block again?
  3. How is this different from PRIMASK?
Hint BASEPRI blocks every exception whose priority value is ≥ BASEPRI. Priority values sit in the top 3 bits.

a) 3 shifted into the top 3 bits gives 3 × 32 = 0x60.

MOV	R0,	#0x60MSR	BASEPRI,	R0

b) Write 0. BASEPRI = 0 means "no masking".

MOV	R0,	#0MSR	BASEPRI,	R0

c) PRIMASK = 1 blocks all interrupts (everything except NMI and HardFault). BASEPRI blocks only from a priority threshold down, so urgent interrupts still get through.

Bubble sort with a SWAP subroutine

Code

Write SORT: R0 = array address, R1 = number of elements. Sort the words in place, smallest first (bubble sort). Use a separate subroutine SWAP that swaps the two words at [R3] and [R3 + 4]. All registers unchanged, including R0 and R1. 9, 3, 7, 1, 8, 2 becomes 1, 2, 3, 7, 8, 9.

Hint Outer loop: n − 1 passes. Inner loop: compare each neighbouring pair, and BL SWAP if they're out of order. SORT calls SWAP, so LR goes in SORT's PUSH.

After each pass the largest remaining value has moved to the end, so n − 1 passes are enough (and this version still compares the full range each pass, which is fine). SUBS R2, R1, #1 then BLS handles n = 0 and n = 1 with one test. SWAP saves its own temporaries, so SORT's R5 and R6 survive the call.

Solution
	AREA	mydata, DATA, READWRITEDATA	DCD	9, 3, 7, 1, 8, 2N	EQU	6	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	LDR	R0, =DATA	MOV	R1, #N	BL	SORT			; DATA = 1 2 3 7 8 9stop	B	stop ; SORT: r0 = address, r1 = count. Sorts the words, smallest first (unsigned).; Bubble sort; calls SWAP, so LR is saved. All registers unchanged.SORT	PUSH	{R2-R6, LR}	SUBS	R2, R1, #1		; r2 = passes left = n - 1	BLS	so_done			; n <= 1: already sortedso_pass	MOV	R3, R0			; r3 = pointer to the pair	MOV	R4, R2			; r4 = comparisons in this passso_cmp	LDR	R5, [R3]	LDR	R6, [R3, #4]	CMP	R5, R6	BLS	so_next			; in order: leave them	BL	SWAP			; swap the words at r3 and r3+4so_next	ADD	R3, R3, #4	SUBS	R4, R4, #1	BNE	so_cmp	SUBS	R2, R2, #1		; the largest is now at the end	BNE	so_passso_done	POP	{R2-R6, LR}	BX	LR ; SWAP: swaps the words at r3 and r3+4. All registers unchanged.SWAP	PUSH	{R5, R6}	LDR	R5, [R3]	LDR	R6, [R3, #4]	STR	R6, [R3]	STR	R5, [R3, #4]	POP	{R5, R6}	BX	LR 	ALIGN	END

W5·24

Sort a signed array

Code

In the style of an earlier EE447 quiz (the wording here is mine). Write a subroutine SWAPARR that sorts the words of the array ARR in ascending order, treating them as signed numbers. The number of elements is passed in R0; the array is at the fixed label ARR. When it returns, every register must have its original value (Check tests this).

Example: 5, −2, 7, 0, −9 becomes −9, −2, 0, 5, 7.

Hint Two nested loops: for each position i, compare ARR[i] with every later ARR[j] and swap when ARR[j] is smaller. Signed means BGE/BLT, not BHS/BLO. [R5, R1, LSL #2] reads the word at index R1 (index × 4 bytes).

An exchange sort: after the inner loop for position i, ARR[i] holds the smallest of ARR[i..n−1], so the array fills up from the front. Three things quizzes check here:

  • Signed comparison: BGE after CMP. With BHS, −9 (0xFFFFFFF7) would count as the largest number.
  • Index addressing: LDR R3, [R5, R1, LSL #2] computes R5 + R1 × 4 without changing R5 or R1.
  • Start at index 0, and stop the outer loop at n − 1. Starting at 1 silently leaves ARR[0] out of the sort.

Also watch for two mistakes that don't assemble: PULL isn't an instruction (it's POP), and END can't be a label, because it's the assembler's end-of-file directive.

Solution
N	EQU	5	AREA	mydata, DATA, READWRITEARR	DCD	5, -2, 7, 0, -9 	AREA	main, CODE, READONLY	THUMB	EXPORT	__main__main	MOV	R0, #N	BL	SWAPARR			; ARR = -9 -2 0 5 7stop	B	stop ; SWAPARR: R0 = number of elements. Sorts the words at ARR, smallest first,; as SIGNED numbers. All registers unchanged.SWAPARR	PUSH	{R1-R6}	LDR	R5, =ARR		; r5 = base address of the array	SUB	R6, R0, #1		; r6 = n - 1 (last index)	MOV	R1, #0			; r1 = i, starts at index 0outer	CMP	R1, R6	BGE	sw_done			; i >= n-1: sorted (also covers n = 0 and 1)	ADD	R2, R1, #1		; r2 = j = i + 1inner	CMP	R2, R0	BGE	next_i			; j = n: this pass is over	LDR	R3, [R5, R1, lsl #2]	; r3 = ARR[i]  (index * 4 = byte offset)	LDR	R4, [R5, R2, lsl #2]	; r4 = ARR[j]	CMP	R4, R3	BGE	no_swap			; SIGNED: ARR[j] >= ARR[i], already in order	STR	R4, [R5, R1, lsl #2]	; swap them	STR	R3, [R5, R2, lsl #2]no_swap	ADD	R2, R2, #1	B	innernext_i	ADD	R1, R1, #1		; ARR[i] now holds the smallest of ARR[i..n-1]	B	outersw_done	POP	{R1-R6}	BX	LR 	ALIGN	END
